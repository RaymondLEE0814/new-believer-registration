# 초등부 새신자 등록 프로그램 개발 워크플로우 (Work Flow)

이 문서는 초등부 새신자 등록 프로그램의 성공적인 개발을 위한 에이전트 간의 협업 순서와 각 단계별 역할을 정의합니다. 전체 작업은 **기획 ➔ 디자인 ➔ 프로그래밍 ➔ 검수**의 순서로 유기적으로 진행됩니다.

---

## 1단계: 기획 (Planner)
**"기획자가 앱의 뼈대를 세우고 사용자 흐름을 정의합니다."**

*   **담당:** 기획자 에이전트
*   **주요 작업:**
    *   새신자 등록에 필요한 필수 정보(이름, 학년, 반, 부모님 연락처, 알러지 여부 등) 도출
    *   모바일/태블릿 환경에서 사용자가 거치게 될 화면 흐름(User Journey) 설계
    *   어떤 정보를 어느 화면에 배치할지 결정하는 와이어프레임 및 화면 설계서 작성
*   **다음 단계로 전달:** 완성된 '요구사항 정의서'와 '화면 설계서'를 디자이너에게 넘깁니다.

## 2단계: 디자인 (Designer)
**"디자이너가 기획안을 바탕으로 친근하고 아름다운 시각적 결과물을 만듭니다."**

*   **담당:** 디자이너 에이전트
*   **주요 작업:**
    *   전달받은 기획안에 아이들에게 친근하고 기독교 복음적인 테마(색상, 일러스트 등)를 적용
    *   모바일과 태블릿 화면에 맞춰 터치하기 쉽고 직관적인 UI/UX 구성
    *   버튼 클릭, 제출 완료 시의 애니메이션 등 사용자 경험(UX) 요소 디자인
*   **다음 단계로 전달:** 완성된 'UI/UX 디자인 시안'과 '디자인 가이드'를 프로그래머에게 넘깁니다.

## 3단계: 프로그래밍 (Programmer)
**"프로그래머가 디자인을 실제 동작하는 안전한 애플리케이션으로 구현합니다."**

*   **담당:** 프로그래머 에이전트
*   **주요 작업:**
    *   디자인 시안을 바탕으로 다양한 기기에서 잘 보이는 반응형 웹 프론트엔드 개발
    *   기획된 요구사항에 맞춰 빈칸 검사, 전화번호 형식 검사 등 폼 유효성 검증 로직 구현
    *   입력된 데이터를 안전하게 저장하고 관리자가 볼 수 있도록 데이터베이스 및 서버 연동
*   **다음 단계로 전달:** 개발이 완료되어 실제 조작이 가능한 '테스트용 앱(또는 링크)'을 검수자에게 넘깁니다.

## 4단계: 검수 및 QA (Reviewer)
**"검수자가 완성된 프로그램을 꼼꼼히 테스트하고 피드백을 진행합니다."**

*   **담당:** 검수 에이전트
*   **주요 작업:**
    *   기획 의도와 디자인에 맞게 모든 기능이 정상적으로 동작하는지 교차 검증
    *   스마트폰, 태블릿 등 다양한 환경과 브라우저에서 화면이 깨지지 않는지 테스트
    *   잘못된 조작이나 인터넷 끊김 등 예외 상황(Edge Case)에서의 오류 발생 여부 점검
*   **피드백 루프:**
    *   수정할 부분(버그나 UI 깨짐 등)이 발견되면 해당 내용이 담긴 리포트를 작성하여 프로그래머/디자이너에게 수정을 요청합니다. 
    *   모든 문제가 해결되고 승인되면 최종 배포합니다.
